# 口语学习系统(Speaking System)

一套经过真实使用打磨的语言口语训练系统。核心闭环:**ChatGPT 项目负责内容与对话**(每日输入/口语练习/复盘/月度模考,四个触发词驱动),**Obsidian 负责资产与度量**(归档、表达库、错误库、仪表盘、路线图),**定时任务负责低频维护**(每晚归集整理、每月模考提醒)。

先判断用户要做哪类操作,再跳到对应小节。动手前**必读** `references/gotchas.md`——所有已知坑和解析契约都在里面,别重新踩。

如果用户是替朋友咨询、或环境不允许自动化(无权限/非本机),把 `references/manual-setup-guide.md` 发给对方——那是写给人类的 15 分钟手动安装指南,不依赖任何 AI 即可完成部署。

## 操作一:全新部署

先问清参数(有合理默认就别逐条问):目标语言(默认英语)、当前水平与目标(默认 B1→C1 一年)、兴趣领域(3-4 个)、Obsidian 仓库位置(优先 iCloud 容器,手机可用;见 gotchas #18)。

1. **Obsidian 侧**:把 `assets/vault-template/` 的**内容**拷成目标仓库里的 `English-Speaking-System/` 目录(种子目录本身叫 vault-template,不叫 English-Speaking-System,别直接整个拷过去);按用户领域改写 `00-Prompts/3-话题库` 和表达库分类小节;改 `06-Roadmap` 的起止日期与季度区间;运行 `scripts/install_plugins.sh <仓库绝对路径>` 安装 Templater+Dataview 并写好热键(Cmd+Shift+E);重启 Obsidian 并实测:仪表盘渲染、Cmd+Shift+E 出现「剪贴板归档」模板。
2. **ChatGPT 侧**:读 `references/project-instruction-template.md`,替换占位符生成项目指令;引导(或经用户同意后用 computer-use 代办)在 ChatGPT 建项目并贴入 Instructions(UI 路径见 gotchas #19,注意 Typeless 遮挡 #16、剪贴板 #17)。
3. **自动化侧**(建议但可选,逐项征求同意):launchd 每晚 git 备份到 `~/.obsidian-backups/`;两个定时任务——每晚 22:15 归集当天日志进表达库/错误库(周日附周报)、每月 1 号模考提醒(季度节点附升级提醒)。定时任务 prompt 里必须写死仓库绝对路径,并强调查重(宁漏勿重)。
4. **端到端验收**(不可省):在项目里发「每日输入」验证文章生成;造一段假复盘写入剪贴板,跑 Cmd+Shift+E 验证 frontmatter 解析;打开仪表盘验证渲染。验收后把测试笔记移出仓库。

## 操作二:参数变更(升级水平/换领域/换语言)

1. 重新生成项目指令(模板见 references),经用户同意后更新到 ChatGPT 项目;同步更新仓库内的 `4-项目指令(完整版).md` 备份、话题库、README 相关字样。
2. 提醒用户:**改指令必开新会话才生效**(gotchas #2);换领域后头几天开场直接点名领域,等新对话攒够、轮换才会自我纠正。
3. 换语言是深改造:除指令外,还需同步归档模板与仪表盘的解析锚点(gotchas #9「解析契约」)。

## 操作三:故障排查

按症状查 gotchas 对应条目:触发词没反应→#1/#2;语音行为异常(缩水/停顿/说母语/不提问)→#4,先给用户当场遥控话术,再考虑硬化指令;归档解析缺字段→#9,拿真实笔记跑正则验证;打卡/统计异常→#10/#13;模板/插件配置改了没生效→#15。修完必须用真实数据验证,不能只改不测。

## 操作四:体检

依次检查:最近日志的 frontmatter 完整性(空字段=解析失败线索)→ 仪表盘各查询是否报错 → 表达库/错误库是否有重复条目(定时任务查重失效的信号)→ 双副本是否一致(diff)→ 备份 git log 是否在持续产生提交 → 定时任务最近运行状态。输出体检报告并修复发现的问题。

## 红线(改造时守住的设计不变量)

一天=一个会话=一次复盘=一次归档;GPT 负责内容、模板负责结构;自动化只做搬运归集,大声朗读永远留给用户;双副本改动必须同步;低频动作靠定时任务不靠记性。完整理由见 gotchas 末节。

# 踩坑知识库(2026-08 实战沉淀)

三天真实使用中修过的所有坑。部署、排障、改造前先读这里,别重新踩一遍。

## ChatGPT 侧

1. **项目 vs 全局自定义指令互相隔离**:项目内对话不加载全局 Custom Instructions,规则必须写进项目 Instructions。用户在项目里发触发词没反应,九成是把规则写错了地方。
2. **改指令必开新会话**:项目指令在会话建立时注入快照,改完指令旧会话(尤其语音)不会更新。所有"改了没生效"先问:开新会话了吗?
3. **Live 语音从对话中开启会新开一个会话**:上下文(如当天文章)不会跟过去。系统设计已把它变成特性:新语音会话热身第一题=凭记忆复述文章。
4. **语音模式的三大偏置**,指令能压制但不能根治:
   - **短回合偏置**:长朗读会被切碎或缩水 → 指令写明"分 4-5 段、段间不停、少于 N 词自己补足";用户可喊 "Keep going" / "Too short, add two more paragraphs"
   - **语言跟随偏置**:用户说中文触发词,它会整段用中文教学 → 指令写"教学内容始终用目标语言"+ 用户喊 "English only, please"
   - **回合终点误判**:列完表达就沉默不问问题 → 指令写"说完第 5 个表达立即主动问第一题"
5. **语音转写会"洗掉"部分口误**(Whisper 自动纠正),纠错保真度:听写麦克风 > Live。深度纠错需求可安排每周 1-2 次文字+听写的「精读日」。
6. **「转录不可用」**:iOS 偶发 bug,该条用户发言未转文字,复盘看不到。重说即可。
7. **项目跨对话记忆不稳定**:错误重测查不到历史时,fallback 是让用户粘贴错误库(指令已含)。
8. **叫「ChatGPT」的 mac 应用可能是 Codex**(bundle com.openai.codex);聊天版是「ChatGPT Classic」(com.openai.chat)。

## Obsidian 侧

9. **归档解析契约**(模板 `English Study 剪贴板归档.md` 与仪表盘共同依赖,改动需同步):
   - frontmatter 键:date/speaking_time/fluency/grammar/vocabulary/communication/overall_score
   - 评分正则需同时兼容 `| Fluency | 4/5 |`(桌面表格)和 `Fluency\t4.5/5`(手机复制拍平成 TAB);实现用 `Fluency[^\d\n]*([\d.]+)\s*\/\s*5`
   - 错误类型统计需同时认 `[时态]` 和 `【语法:主谓一致】`(GPT 会自选括号);正则 `[\[【]([^\]】\n]{1,16})[\]】]`,冒号(半角+**全角 U+FF1A**)前取大类——全角冒号在编辑器里极易被写成半角,务必用字节校验
   - 手机复制会丢失 `#` 标题:模板的无-`#` 分支会重建 `#`/`##` 结构,小节名单里必须包含全部模板小节(含 Error Log、弯引号变体 Tomorrow's)
10. **连续打卡必须基于「有 date 的笔记」**而不是「有 overall_score 的笔记」,否则解析失败的那天会误判断签。
    - ⚠️ 前提是 date 本身要对。见 #22——date 曾经取的是归档时刻,打卡因此长期报错。

22. **归档日期必须取自复盘正文,不能用 `tp.date.now()`**(2026-08-09 修正)。原模板 `const dateStr = tp.date.now("YYYY-MM-DD")`,还主动把 GPT 写对的标题日期覆盖掉(`body.replace(/^#[^\n]*English Study[^\n]*$/m, ...)`),frontmatter `date:` 和文件名全用它。结果:**晚上练、隔天归档,或补档几天前的记录,日志会被盖成归档那天**。实测 8 篇里 3 篇 date 错、两篇撞同一天,仪表盘打卡从 8 天变成显示 1 天,趋势图标签错位,连按 date 找日志的定时整理都连着漏了 3 天没整理(表现为"任务跑了但没收录",极易误判成查重逻辑出问题)。
    - 正确做法:`clip.match(/(20\d{2}-\d{2}-\d{2})\s*English Study/i)` 取练习日期,取不到或超过明天才回退 `tp.date.now()`。同时在项目指令里写死"[Date] 填练习当天、标题格式固定 `# YYYY-MM-DD English Study`"。
    - 排查信号:**文件名日期和 frontmatter date 不一致**。体检时把这条当必查项——`for f in *.md; do 比对 ${f:0:10} 与 grep '^date:'; done`。

23. **改评分口径必须同时改承载它的字段**,否则新口径只活在 GPT 的输出文字里、进不了数据层。2026-08-09 把 Grammar 换成每百词错误率时,frontmatter 没有词数字段,仪表盘只能继续用旧的 ÷分钟,趋势图和评分表当场自相矛盾。配套要加:模板 Speaking Time 小节增 `Scored speaking time:` / `Scored word count:` / `Errors per 100 words:` 三行 → 归档模板解析成 `scored_time` / `word_count` / `error_rate` → 仪表盘优先读 `error_rate`。**数字必须逐行写在小节里,不能只写在评分表的说明栏**——表格单元格解析不可靠。
11. **Templater 文件夹自动模板(folder template)在 v2.24 不可靠**:新建文件不触发。别把它当归档路径承诺给用户;唯一归档路径= `Cmd+Shift+E` → create-new-note-from-template。
12. **新建笔记会继承当前活动笔记的属性**(Obsidian 1.13 行为):开着仪表盘归档会混入 `dashboard` 标签。无害,统计按文件夹+字段过滤,不按标签。
13. **同天多次归档**:模板检测重名自动加 HHmm 后缀;仪表盘按「次」统计、打卡按「天」去重——这是有意语义,别改。
14. **仪表盘用阅读模式打开**:编辑模式下误敲键盘会把字符写进笔记(发生过)。
15. **外部修改插件 data.json 后必须重启 Obsidian**;Templater 运行中会按自己内存里的配置回写。

## macOS 自动化侧

16. **Typeless 听写工具有透明悬浮窗**,挡屏幕中下部点击(跟随输入光标)。UI 自动化前 `osascript -e 'tell application "Typeless" to quit'`,完事 `open -a Typeless` 恢复。
17. **沙盒 Bash 里 pbcopy 写不进系统剪贴板**:给 UI 粘贴准备内容必须用授权的剪贴板工具(write_clipboard),不能用 pbcopy。
18. **手机版 Obsidian 只能打开 iCloud 容器内的仓库**:`~/Library/Mobile Documents/iCloud~md~obsidian/Documents/`。迁移=拷贝+校验+改 `~/Library/Application Support/obsidian/obsidian.json` 的 path+重启;旧目录改名保留作回退。手机首开的信号是 `.obsidian/workspace-mobile.json` 同步回来。
19. **ChatGPT 桌面版 UI 自动化路径**:app 菜单→设置(cmd+, 不可靠);项目指令入口=项目页右上 ⋯ →「编辑指令」;保存后弹窗自动关闭即成功。粘贴后用 zoom 截图校验开头文字再保存。

20. **评分漂移**:不给量表时,LLM 评分会央值黏滞(Grammar 永远 3.5)且混淆难度与能力(短而简单的闲聊反而拿高分)。修复=证据锚定评分:Grammar 绑定错误率(量表见指令模板),Overall=加权和×2 纯计算,「说明」栏强制引用证据数字。注意:切换量表当天起,历史分数与新分数不可比——要提前告诉用户这是测量变准了,不是退步。

21. **错误率的分母必须是词数,不能是分钟**(2026-08-09 修正,原量表用的是「错误条数÷发言分钟」):因为 `错误数/分钟 = (错误数/词数) × (词数/分钟) = 准确率 × 语速`,语速会被算两次——在 Fluency 里当奖励、又在 Grammar 里当惩罚。后果是准确率完全没变、只是说快了,Grammar 就自动掉档;刻意放慢少说则假性涨分。而两边权重相抵后 `ΔOverall ≈ +0.3`,几乎是平局,等于系统不给方向,用户会陷入"该说慢还是该冲量"的两难。改成每百词错误数后两个轴正交:语速只进 Fluency,Grammar 只反映真实准确率。
    - 换分母会**放大**#20 提到的"短而简单拿高分"倾向(说安全的短句 → 错误率天然低),所以必须配一条**反简单化封顶**:复杂结构不足 3 个时 Grammar 封顶 4.0。这条和「尝试复杂结构 +0.25」是一对,别只抄一半。
    - 档位若要重设,先拿用户最近 5-6 篇日志反算每百词错误率再定档,让新旧分数尽量接续,否则仪表盘趋势会出现假断层。

31. **GPT 写数字会带千分位逗号**("Scored word count: ~1,520"),`\d+` 解析在逗号处截断,word_count 存成 1——仪表盘上表现为「评分词数=1」而错误率却正常(错误率是 GPT 直接给的)。解析大数字一律用 `([\d,]+)` 再 strip 逗号。排查信号:word_count 与 scored_time 严重不成比例(23 分钟只有 1 词)。

## 系统设计不变量(改造时守住)

- **一天 = 一个会话 = 一次复盘 = 一次归档**。任何让用户一天做两次复盘的设计都是打补丁,应重新划分会话边界。
- **GPT 负责内容,模板负责结构**:格式统一才有数据;评分才能画线。
- **自动化搬运,人工朗读**:整理归集全自动;大声朗读错误库/金句是唯一必须留给用户的动作。
- **双副本同步**:vault 内是运行时,源目录(如 Pennys-tool)是版本基准;改任一份必须同步另一份。
- **低频动作全部定时化**(每晚整理、每月提醒),不依赖用户记性。

24. **表达没有回收环节**(2026-08-10 补):原设计里错误是闭环(犯错→错误库→热身重测→已攻克),表达是**开环**——学完当天操练一次就永久躺在库里。用户的主诉「学了用不上」根源在这。修法三层:入库分级(主动队列封顶 40 条,其余只读)+ 热身加**产出式**表达重测(给中文情境让他说英文,不能先念英文否则变跟读)+ 任务卡强制在对话里自发用出,自发 2 次才毕业。度量用「表达激活率」,否则表达库只增不减、无从判断吸收率。
    - 吞吐必须先算:该用户 65 条/周入库,而热身 5-6 条/次 × 7 天 ÷ 3.5 次曝光 ≈ 12 条/周消化能力,**超载 5 倍**。不封顶队列,两周内必然堆爆放弃。

25. **「自由对话」是整条链上唯一没有内容供给的环节**,所以它必然最先崩——用户表现为「练着练着没话题了,时长撑不满」。不要靠加时长或话题库(那还是要用户自己挑)解决,把它换成**按星期轮换的结构化输出任务**(观点陈述/角色扮演/换受众重讲/辩论/案例诊断/个人故事/周串讲),题目由 GPT 出。另配一条「不许提前结束、环节提前完成就追问加深、只有用户说停才停」的硬规则。

26. **ChatGPT 读不到 Obsidian,但不必靠粘贴或浏览器自动化解决**。最稳的是**滚动队列**:让每天的复盘固定输出「明日重测清单」,第二天开练时 GPT 只需读**最近一次对话**就拿到队列——依赖的是"找最近一次复盘",比 gotcha #7 说的"全历史检索"可靠得多,且**语音模式下同样有效**(联网/读文件在 Live 里都不可靠)。夜间任务改指令那种方案看着自动,实则依赖浏览器登录态+UI 不变,脆得多。

27. **ChatGPT 项目指令输入框是 React 受控组件**:程序化写 DOM `value`(含 MCP 的 form_input)不会触发 React 状态更新,点保存后弹窗照常自动关闭——**看起来成功,实际提交的还是旧内容**。必须用真实键盘事件(全选后逐字输入)。另:在已滚动的 textarea 里靠点击定位光标极不可靠(实测插到了词中间),要改就全选重打。改完务必重新加载页面再读一次校验,别信弹窗关闭。

28. **Spaced Repetition 插件 v1.15+ 把配置嵌套在 `settings` 键里**,外部写的**顶层** data.json 键会被静默忽略。实测:我按旧结构写了顶层 `flashcardTags: ["#flashcard"]`,插件加载后仍用默认的 `["#flashcards"]`(**复数**),卡组标签是单数 → 插件一张卡都找不到,而且**不报错**。
    - 判断插件到底读到了什么:`data.json` 里 `settings.flashcardTags`,不是顶层同名键。
    - 最省事的做法是**顺着插件默认值走**(卡组用 `#flashcards`),别去改它的配置——改了还要重启,且下次插件升级可能再变结构。
    - 插件是否真的加载了,有个可靠的磁盘信号:重启后 data.json 被重写,并出现 `settings` / `buryDate` / `buryList` / `historyDeck` / `scheduleData` 这些运行时键——只有插件自己会写。
    - **命令名会因缺翻译而回退英文**:命令 `srs-review-flashcards` 取名自 `REVIEW_ALL_CARDS`,而该词条**没有中文翻译**(12 个语言里无 zh),所以中文界面下它显示的是英文全名 **「Spaced Repetition: Review flashcards from all notes」**——不是插件文档里写的 "Review flashcards",按后者搜命令面板会「未找到命令」,极易误判成插件没装好。给用户的话直接让他搜 `flashcards` 最稳。
    - 判断插件是否真在工作,最直观的是**状态栏右下角的 `N card(s) due`**——有数字就说明卡组被扫到了,与命令名无关。

29. **改了流程就必须回头检查评分口径的措辞**(2026-08-10 实伤)。先写下"评分样本只取**自由讨论**与回答问题的部分"(本意只排除搭配操练),第二天又把"自由对话"整个换成了"输出任务"——GPT 按字面把输出任务也当成任务排除了,结果 25 分钟发言只有 4.5 分钟/270 词进评分,15 个错误摊在 270 词上 = 3.3/百词,Grammar 被压到 2.75,用户当天体感"越练分越低",实际那天是历史最好的一次(时长最长、错误率最低)。
    - 教训:**口径按"排除什么"来写,不要按"包含什么"来写**——环节名一改,白名单就失效,黑名单不会。
    - 加一条自检给 GPT:Scored speaking time 应占总发言 60% 以上,不足一半就是排除过头,重算。
    - 排查信号:frontmatter 里 `scored_time` 远小于 `speaking_time`,或 Overall 说明里出现"样本偏小"。

30. **在 ChatGPT 网页上追加文本时,别用"点击定位光标"**。可靠做法:点进 textarea → `cmd+a` 全选 → 按 `→`(把选区塌缩到末尾)→ 直接输入。另外**批量点击「⋯ → 项目设置」经常打不开对话框**,而 JS 读不到 textarea 时返回的是"未找到",极易误判成保存失败——每一步都要截图确认对话框真的开了再往下走。有一次对话框没开,追加的文字直接打进了聊天输入框(所幸没发送)。

# 让 AI 每晚替你整理(进阶,需要本地 AI 助手)

> 系统自带的「自动整理」启动脚本只能**机械搬运**(把新表达丢进「待归类」区等你手动分类)。
> 如果你有能跑定时任务的 AI 助手,可以升级成**每晚智能整理**:自动归类、合并相似错误、统计「学了用没用上」、还顺手给你做系统体检。
>
> 这一页给你完整的任务提示词。**没有 AI 助手完全不影响使用**——启动脚本 + 每周 5 分钟手动归类同样能跑。

---

## 两者差在哪

| | 启动脚本(内置) | AI 每晚整理 |
|---|---|---|
| 表达归类 | 全丢进「📥 待归类」,你手动挪 | 读懂语义直接归到正确领域 |
| 相似错误 | 字符串匹配,`build trust` 和 `build the trust` 算两条 | 认出是同一个错误,合并并标重犯 |
| 使用记录 | ❌ 做不到 | 累计「自发用出」次数,满 2 次判定毕业 🎓 |
| 发音音频 | ❌ | 顺手生成(macOS) |
| 质量守卫 | ❌ | 8 项体检,数据出问题时报警 |
| 反馈 | 一条通知 | 每日简报 + 周日周报 |

⚠️ **两者只能开一个**。都开的话,启动脚本会先把表达搬进「待归类」区,AI 晚上再看日志时发现"已存在"就跳过了,结果表达永远卡在待归类区。用 AI 版就别开启动脚本(反之亦然)。

---

## 怎么配

### 如果你用 Claude Code

直接对它说:

```
帮我创建一个每晚 22:15 运行的定时任务,任务内容就用
https://raw.githubusercontent.com/Penny777btc/speaking-system/main/docs/AI每晚自动整理.md
里「任务提示词」那一节,把里面的 {{VAULT}} 换成 <你的 Obsidian 仓库路径>、
{{REPO}} 换成 <你解压的 speaking-system 目录>
```

### 如果你用 Codex 或其他 CLI 型 agent

Codex 本身没有调度器,用系统的 cron 调它。先把提示词存成一个文件(比如 `~/english-nightly.txt`,记得替换占位符),然后:

```bash
crontab -e
```

加一行(每晚 22:15):

```
15 22 * * * /Applications/ChatGPT.app/Contents/Resources/codex exec --approve-for-me --skip-git-repo-check -c 'sandbox_workspace_write.network_access=true' "$(cat ~/english-nightly.txt)" >> ~/english-nightly.log 2>&1
```

> Linux/Windows 用你各自的调度器(cron / 任务计划程序),原理一样:定时把提示词喂给 agent。

### 时间怎么选

设在你**通常练完之后**。任务会自动处理「最近 2 天」的日志,所以偶尔晚一天归档也不会漏。

## 任务提示词

> 复制下面整段,替换两个占位符:
> - `{{VAULT}}` → 你的 Obsidian 仓库路径(例:`/Users/you/Documents/MyVault`)
> - `{{REPO}}` → 你下载解压的 speaking-system 目录(例:`/Users/you/Downloads/speaking-system-main`)

```
你是用户英语口语学习系统的每日整理助手。用户用「ChatGPT 项目 + Obsidian」练口语,每天的练习复盘会归档为 Markdown 笔记。

系统路径:{{VAULT}}/English-Speaking-System

每天执行:

1. 读取 02-Daily-Logs/ 里最近 2 天的日志(文件名 "YYYY-MM-DD English Study*.md",以 frontmatter 的 date 为准;取 2 天是为了兜住跨天补档)。如果没有新内容,输出一句「今日无新增,当前打卡 X 天」,然后仍要执行第 6 步体检。

2. 更新表达库 03-Expression-Bank/Expression Bank.md:把新日志「New Words & Phrases」和「Model Sentence」里的表达按现有分类追加,每条标注日期;**先检查是否已存在,绝不重复添加**;好金句加进「⭐ 本周金句」区。
   - 格式必须是 `- expression *(YYYY-MM-DD,中文意思)*` ——闪卡靠这个中文做卡片正面,没有中文的条目会被跳过。
   - 括号里只放**对这个表达本身的解释**,不要放来源标签或编辑说明,那会变成无效的卡片正面。
   - 每条新表达再配一句例句,写成 `- expression — *Example sentence.* *(YYYY-MM-DD,中文意思)*`(例句放表达和日期之间,闪卡会把它放到卡片背面)。例句要求:**原样包含该表达本身**(不要变形、不要换同义词)、场景取自用户的兴趣领域、单句 15–20 词;如果用户在日志里已经自己说对过含这个表达的句子,**优先直接用他自己那句原句**。
   - 分类不存在就新建一个小节;分类名跟着用户的兴趣领域走。

3. 处理新日志里的「## Expressions Used」:把「自发用出」的表达,在表达库对应条目末尾补注 `· 用过 ×N · 上次 MM-DD`(已有就 N 加一、更新日期);自发累计满 2 次的在条目后加 `🎓`。这是「学了到底用没用上」的唯一数据来源,不能跳过;日志里没有这一节就跳过并在简报里提一句。

4. 更新错误库 04-Error-Patterns/Error Patterns.md:把新日志「Key Corrections」和「Error Log」的错误按类型归入现有分类,保持 ❌→✅ 格式;**与库中已有条目相同或高度相似的错误不重复添加**,而是在原条目后补注新日期——这类"再犯"错误累计 ≥2 次就移入顶部「🔥 高频重犯」区。不虚构任何内容。

5. (可选,仅 macOS)重新生成复习闪卡并配发音:
   python3 {{REPO}}/scripts/build_flashcards.py "{{VAULT}}/English-Speaking-System"
   它会覆盖写 07-Review/表达闪卡.md,并用系统 say 把新表达录进 07-Review/audio/。脚本会自动保留复习进度;若输出里 schedules-kept 两个数字不相等,说明有旧卡片对不上(表达被改写或删除),在简报里提一句。

6. 系统体检(**只读,不修改任何文件**;每一项都对应真实发生过的静默故障):
   a. 日期一致性:每篇日志的文件名前 10 位应等于 frontmatter 的 date,不一致的列出来(会导致打卡天数和趋势图错乱)。
   b. 字段合理性(只查最近 7 天):word_count ÷ scored_time 应在 40–200 之间;error_rate 和 word_count 不应为空或 0。
   c. 评分样本占比:scored_time ÷ speaking_time 应 ≥0.5。低于 0.5 报警并提示「AI 排除过头,当天分数偏低,可让 ChatGPT 重算」。
   d. 总分自洽:按四维分重算 (fluency×0.3 + communication×0.3 + grammar×0.2 + vocabulary×0.2)×2,与 overall_score 差 >0.1 就报警并给出正确值。
   e. 云端驻留:若某篇日志磁盘大小 >0 但读取内容为空,提示用户在原设备上打开一次触发同步。
   f. 闪卡产物:07-Review/表达闪卡.md 存在且含卡片。
   g. 今日收录确认:若存在 date=今天的日志但第 1 步没处理到,报警。

7. 输出简报:
   - 平日:4 行以内——今天新增表达 N 条、新增/再犯错误 N 条、自发用出 N 个(毕业 N 个)、连续打卡 N 天;末行体检结果,全过写「体检 ✓」,有异常则列「⚠️ <项目>—<现象>—<一句修复建议>」。
   - 周日:额外附完整周报(15 行内):本周练习次数与总时长、每天的 overall_score 趋势、错误类型 Top3 及与上周对比、新增表达总数、表达激活率(自发用出过的 / 表达库总数)与毕业条数,结尾提醒「大声朗读一遍错误库的正确版本」。

约束:不要修改 02-Daily-Logs 里的日志原文;不要删除表达库/错误库的既有内容;宁可漏收录也不要重复收录;体检环节绝对只读。
```

---

## 配好之后

**关掉启动脚本**(如果之前开过):Obsidian 设置 → Templater → Startup templates 列表里移除「自动整理.md」。两套只留一套。

第一次运行建议手动触发一次,把权限一次性批准好,之后就全自动了。

---

## 它做不到的两件事

1. **替你朗读错误库** —— 这是唯一必须你自己做的学习动作,自动化它等于请人替你健身
2. **碰你的 ChatGPT** —— 云端封闭,所以每天的「复制 + `Cmd+Shift+E` 归档」仍然要你动手
